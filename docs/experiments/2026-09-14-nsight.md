배치 2는 한 번에 두 로봇을 처리하지만 호출 한 번은 더 오래 걸렸다. 이는 동적 스케줄링 중 관측된 값이며, 동일 입력·동일 상태로 비교한 고정 batch microbenchmark 결과가 아니다.

연속된 추론 87회의 첫 시작부터 마지막 끝까지는 15.121초이고, 그중 infer_batch NVTX 범위 합계는 14.709초(97.27%)였다. 호출 사이 86개 간격은 합계 412.09ms, 평균 4.79ms, p95 7.43ms, 최대 7.92ms였다. 따라서 이 구간에서 긴 추론 호출 사이 공백이 전체 시간의 큰 비중을 차지했다고 보기는 어렵다. 이 값은 추론 함수 내부의 GPU 계산·복사·host 작업·완료 대기를 함께 포함하므로 GPU utilization 97%를 뜻하지 않는다. 스케줄러 선택이 로봇의 action 부족에 미친 영향을 배제하는 근거도 아니다.

GPU에서 기록된 memcpy 이벤트는 Host→Device 1,672회/7.03ms, Device→Host 1,228회/1.47ms, Device→Device 83,377회/1,468.08ms였다. 합산 복사 시간의 대부분은 GPU 내부 복사였다. 이 시간은 CUDA 복사 이벤트의 duration 합계이며, CPU 직렬화나 WebSocket 전송 시간을 뜻하지 않는다. 따라서 이 표만으로 이미지 전송 비용이 작다거나 네트워크가 병목이 아니라고 결론 내릴 수 없다.

CUDA API 호출 중 cuStreamSynchronize의 elapsed 합계는 9.344초였다. 이 값은 호출을 수행한 host 측 경과 시간이며 GPU 실행과 겹칠 수 있다. 추론 시간이나 CUDA 활동 시간에 더하거나 전부 낭비 시간으로 계산하면 안 된다. 호출의 크기만으로 불필요한 동기화인지 필요한 계산 완료 대기인지 판정하지 않았다.

수집된 CUDA Graph·kernel·memcpy·memset 범위의 합집합은 11.782초였다. CUDA Graph 범위는 내부 공백을 포함할 수 있고, 별도 LIBERO 렌더링 프로세스도 수집 대상에 포함되지 않았다. 이를 GPU 전체의 busy 시간이나 SM 활용률로 치환하지 않는다. raw nvtx_sum의 수집 경계에서 닫히지 않은 범위도 제외해야 한다.

현재 근거로는 추론 호출 내부 비용을 더 세분화할 가치가 있다고 판단한다. 그러나 GPU 계산, host dispatch, GPU 내부 복사, 동기화 중 무엇이 지배적 병목인지, 또는 4개 로봇에서 최대 배치 2가 4보다 유리했던 직접 원인인지는 아직 확정하지 않았다. 현재 Nsight는 2개 로봇·최대 배치 2 조건만 담고 있기 때문이다.
